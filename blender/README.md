# The animals, in Blender

Every animal in the game is modelled, rigged and animated here. The game draws
exactly what `animals.blend` contains.

```
blender/animals.py      builds animals.blend from scratch, then exports it
blender/animals.blend   the source: 20 animals, 2 rigs, 23 actions
parts/02d_models.js     GENERATED by the export: what the game actually loads
```

## Workflows

**Change something by editing the script** (shapes, colours, a clip's motion):

```
pip install bpy            # Blender as a Python module, 4.2
python3 blender/animals.py # rebuilds animals.blend and re-exports
python3 build.py && cp chickens-vs-raccoons.html index.html
```

**Change something by hand in Blender** (move vertices, re-key an action):

1. Open `blender/animals.blend`, edit, save.
2. `python3 blender/animals.py --export-only` — or, inside Blender,
   `blender -b blender/animals.blend -P blender/animals.py -- --export-only`.
3. Rebuild the page as above.

A full run of `animals.py` (without `--export-only`) regenerates the `.blend`
from the script, so hand edits are lost. Hand edits and the script can both be
used, but not at the same time. Pick one, or copy the hand edit back into the
script.

## What is in the file

One collection per animal. Each has an armature (`hen`, `bull`…) and three
meshes parented to it: `hen.lod0` (close-ups and ordinary fights, about 1000
triangles), `hen.lod1` (a crowd, about 500) and `hen.lod2` (the horde, about
270). Only lod0 is visible; the others are hidden in the viewport.
Each mesh has one material per colour slot, named `hen.feather`, `hen.red`
and so on. The material colour is only a preview of variant 0. The game's
colour variants are stored on the armature as the custom property `variants`,
so recolouring means editing that property or `SPECIES` in the script.

Actions are named `rig.clip` (`bird.walk`, `quad.kick`…) and are shared by
every animal on that rig. Custom properties on each action say how the game
plays it: `clip_frames`, `clip_loop`, and for attacks `clip_contact` (0.4 —
the blow lands 40% of the way through).

| Rig | Animals | Bones |
|---|---|---|
| `bird` | hen, rooster, gamecock, guinea, goose, turkey, hawk | body, neck, head, wing/wingtip ×2, tail, leg/foot ×2 |
| `quad` | cat, capybara, goat, pig, llama, donkey, dog, bull, raccoon, possum, fox, coyote, bear | body, chest, neck, head, jaw, tail1, tail2, 4 legs × upper/lower |

| Clip | Used for |
|---|---|
| idle, walk, run | standing, moving, panicking (the game picks by speed and state) |
| flail | thrown through the air |
| flinch | just got hit |
| die | the collapse (the game rolls the body onto its side) |
| fly, glide | the hawk, low and flapping or high and soaring |
| peck, flog, wingatk, strike | bird attacks: hens/roosters/guinea, gamecock, goose/turkey, hawk |
| bite, butt, kick, swipe, spit | quad attacks: dogs/foxes/coyotes/possum/capybara, goat/pig/bull, donkey, bear/cat/raccoon, llama |

Which attack an animal uses is the `atk` custom property on its armature.

## Rules the game depends on

- **Bones are world-aligned.** Every bone sits at its joint and points
  straight up with no roll, so its local axes are the game's axes for every
  animal. Local X is pitch, Y is yaw, Z is roll. That is why one action fits
  a hen and a turkey: "rotate the neck 0.5 about X" means the same thing on
  both. Don't reorient bones. If you add one, make it point up with roll 0.
- **Rotation only.** Clips must not move or scale bones. The game moves the
  whole animal itself (position, heading, lean, recoil, tumble, lying down).
  The exporter reads only `rotation_quaternion`.
- **Rigid weights.** Every vertex belongs 100% to one bone, which is what lets
  the game skin five thousand animals from a texture. Use one vertex group per
  vertex. The exporter takes the heaviest group.
- **At most 16 colour slots per animal and 4 colour variants.** The game's
  palette is sized for that.
- **Keep lod meshes as separate islands of up to 256 vertices.** The packer
  indexes each island with one byte and falls back to two bytes if an island
  is bigger. That still works, it's just larger.

## How the game uses it

`parts/03b_skin.js`, at load, walks each species' rest skeleton through every
frame of its rig's clips and bakes the resulting bone matrices into a small
half-float texture: one row per frame, three texels per bone. Each animal on
the field is one instance of its species' mesh plus four numbers: two clip rows
and a blend weight between them, and its colour variant. The vertex shader
reads two matrices, blends them, and places the vertex. Rows are fractional
and the texture filters linearly, so frames interpolate for free.

`renderAgents()` in `parts/05_view.js` chooses the rows each frame from the
simulation's state: idle and walk blended by speed, run when panicking, the
attack clip timed so its contact frame lands on the exact step the damage
does, flinch on a hit, die when dead, flail when thrown. Nothing there is read
by the simulation or draws from the seeded stream, so fights replay
identically.
